# kore-plugin-logs (плагин просмотра и анализа журналов)

## Что делает плагин

Читает реальные файлы журналов хоста и systemd journal: список разрешённых источников, чтение хвоста, блочный поиск по всему файлу, статистика, блочная загрузка, продолжение по курсору, агрегация нескольких источников и ротация. Производственный уровень. Никаких образцов в памяти и встроенного содержимого журналов.

Возможность уровня плагина system:read; методы только для чтения используют system:read, изменяющие методы (rotate, retention.set) — system:admin.

## Ключевые моменты

- Нет чтения целиком: tail сканирует назад блоками по 64 КиБ, search — вперёд; жёсткие лимиты 64 МиБ на сканирование и 8 КиБ на строку, поэтому журналы в ГБ никогда не загружаются полностью.
- Список разрешённых источников: принимаются только имена из KORE_LOGS_SOURCES; запросы не содержат путей, ответы не раскрывают абсолютные пути хоста.
- Протокол kore.plugin.v1 через UDS, внедряемый ядром; рукопожатие kore.hello и цикл сессии; stdout зарезервирован для кадров протокола, журналы пишутся в stderr.
- Методы: logs.sources, logs.tail, logs.search, logs.stats, logs.download, logs.follow, logs.aggregate, logs.rotate, logs.retention.get/.set, logs.usage (полные таблицы в DETAIL.md).

## Установка и проверка

Установите `logs` из маркетплейса плагинов или импортируйте dist/logs-0.5.4.tar.gz, собранный через make dist. Проверка: make check (gofmt, go vet, go test -timeout 200s), включая наборы boundary, fault и e2e.
